# $bog_rec

Запись и детерминированное проигрывание сессий $mol-приложения.

- Просмотрщик: https://b-on-g.github.io/rec/
- Подопытное приложение: https://b-on-g.github.io/rec/demo/

Сервисы вроде Sentry Replay пишут DOM: полный снимок дерева плюс поток мутаций.
Так приходится делать, когда до состояния приложения не дотянуться. В $mol вьюха —
чистая функция состояния, поэтому писать надо вход, а не выход. Лог получается на
три порядка меньше видео, а на выходе не картинка, а живое приложение: его можно
остановить, полистать состояние, отмотать назад и продолжить.

Четырнадцать событий занимают 2.7 КБ и проигрываются за 7 мс.

## Из чего состоит

- `$bog_rec` — формат записи.
- `$bog_rec_hook` — единственная точка перехвата событий: подменяет `event_async` у `$mol_view`.
- `$bog_rec_take` — рекордер.
- `$bog_rec_clock` — виртуальные часы и очередь таймеров.
- `$bog_rec_rand` — детерминированный ГПСЧ.
- `$bog_rec_play` — плеер: поднимает бандл во фрейме с подменённым окружением.
- `$bog_rec_fuzz` — прокликиватель: обходит дерево видов и дёргает их обработчики.
- `$bog_rec_app` — просмотрщик записей.
- `$bog_rec_demo` — подопытное приложение.

## Как записывать

В meta.tree приложения:

```tree
include \/bog/rec/take/auto
```

Запись начнётся при загрузке бандла и больше ничего не потребует.

Тонкой настройкой вместо `take/auto` рекордер подключают руками:

```ts
$bog_rec_take.start({
	mask: path => /Password|Secret/.test( path ),   // закрыть значения этих полей
	keys: key => key.startsWith( '$bog_music' ),     // что брать из хранилищ
	calls: true,                                     // писать тела ответов бэка
	keep: true,                                      // откладывать в localStorage
	sink: 'https://example.org/rec',                 // слать при уходе со страницы
})
```

Простые настройки (`keep`, `sink`, `calls`) можно взвести из консоли так, чтобы они
пережили перезагрузку: `$bog_rec_take.arm({ keep: true })`. Автозапуск читает их
при следующей загрузке.

## Как забрать запись

**Кнопки для этого нет и не будет.** Рекордер не имеет права подмешивать свой
интерфейс в чужое приложение: он подключается одной строкой в meta.tree и обязан
после этого молчать. Забирают запись снаружи, из консоли.

(У подопытного приложения кнопка есть, но это его собственная кнопка, а не
рекордера: демка для того и существует, чтобы запись было удобно получить.)

Просмотрщик и приложение живут на разных адресах, поэтому переносить запись
через `localStorage` не выйдет: хранилище у каждого origin своё. Транспорт —
файл, ему origin безразличен.

### Вариант 1: без перезагрузки

Обычный случай. Баг воспроизвели, страница жива.

Открыть DevTools **на вкладке приложения** и выполнить:

```js
$bog_rec_take.save()
```

Браузер скачает `$bog_music_app-K3F9QZ1A.rec.json`. Дальше открыть просмотрщик
и выбрать этот файл кнопкой загрузки. Запись при этом не прерывается, можно
продолжать щёлкать и сохранить ещё раз.

Когда файл неудобен, например надо переслать в чат, тот же JSON забирается текстом:

```js
copy( $bog_rec_take.text() )
```

`copy()` — встроенная функция DevTools, в коде страницы её нет.

### Вариант 2: с перезагрузкой

Баг роняет страницу, уводит с неё или воспроизводится только на свежей загрузке.
Тогда автосброс взводят заранее, одной командой:

```js
$bog_rec_take.arm({ keep: true })
```

Настройка ложится в `localStorage` приложения и переживает перезагрузку: автозапуск
читает её при следующей загрузке. Теперь при каждом уходе со страницы (перезагрузка,
переход, сворачивание вкладки) рекордер сам сбрасывает запись в хранилище.

Дальше воспроизводим баг, страница перезагружается. Возвращаемся в консоль и забираем
запись **до того, как её перетрёт следующая**:

```js
$bog_rec_take.save( $bog_rec_take.stored() )   // скачать отложенную
$bog_rec_take.forget()                          // убрать её из хранилища
$bog_rec_take.disarm()                          // снять взвод, когда наигрались
```

Полный сценарий целиком:

```js
// один раз, перед охотой на баг
$bog_rec_take.arm({ keep: true })

// ...воспроизводим баг, страница перезагружается...

// после возвращения
$bog_rec_take.save( $bog_rec_take.stored() )
$bog_rec_take.forget()
$bog_rec_take.disarm()
```

Оговорка: сброс висит на `pagehide` и `visibilitychange`. Мягкое падение и
перезагрузку это переживает, а жёсткий вылет вкладки, когда браузер убивает
процесс, — уже нет.

### Прислать на сервер

Когда запись нужна не со своей машины, а от пользователя, `sink` шлёт её POST-запросом
при уходе со страницы, с `keepalive: true`, поэтому она переживает закрытие вкладки:

```js
$bog_rec_take.arm({ keep: true, sink: 'https://example.org/rec' })
```

Учтите потолок: браузеры ограничивают тело `keepalive`-запроса 64 КБ, длинную
сессию придётся резать или слать самому.

Отправка идёт мимо собственной обёртки над `fetch`, поэтому в запись не попадает.

### Из чужой вкладки

Когда консоль под рукой, а лезть в неё не хочется, годится закладка:

```
javascript:$bog_rec_take.save()
```

## Что попадает в запись

События с путём вида (`$bog_music_app.Root<0>.Player<>.Play<>`), ответы бэка,
стартовые `localStorage` и `sessionStorage`, хвост адреса, язык и тему документа,
размер окна и ленты значений `Math.random` с `crypto.randomUUID`. Время не пишется
поштучно: плеер крутит виртуальные часы по временной шкале событий.

Значения полей пишутся как есть, иначе реплей уедет на первом же поиске.
Пароли не пишутся никогда, всё остальное закрывается через `mask`.

Из хранилищ по умолчанию берутся только свои ключи: на общем origin (тот же
дев-сервер) рядом лежит состояние всех приложений воркспейса. Отбор при
необходимости задаётся через `keys`.

## Как проигрывать

Открыть просмотрщик и выбрать файл записи. Приложение поднимется тем же
бандлом в изолированном фрейме, где подменены часы, таймеры, случайность,
сеть и хранилища.

Запись, лежащую по адресу, можно открыть сразу: `#!rec=https://.../session.rec.json`.

Шаг назад делается пересборкой фрейма и быстрым проигрыванием вперёд.
Снимки состояния не нужны ровно потому, что проигрывание детерминировано.

## Прокликивание вместо Playwright

`$bog_rec_fuzz` обходит дерево видов, берёт у каждого объявленный `event()`
и дёргает обработчики. Селекторы и разметка для тестов не нужны: у каждого
вида уже есть путь и список событий.

```ts
const report = await $bog_rec_fuzz.run({ root: $bog_music_app.Root(0), steps: 200 })
if( report.errors.length ) $bog_rec_take.save( report.session )
```

Прогон идёт с включённым рекордером, поэтому падение оставляет после себя
запись, которую плеер проиграет столько раз, сколько надо.

## Ограничения

- Проигрывать запись можно только тем бандлом, которым она сделана. Адрес бандла лежит в записи; `-/web.js` самодостаточен, так что достаточно положить его рядом.
- Фрейм поднимается через `srcdoc` и наследует origin просмотрщика. Для чужого бандла это означает, что его код исполнится в вашем origin.
- Событие отправляется на узел вида-владельца обработчика, а не на исходный `event.target` глубже по дереву. Обработчикам, которые смотрят на `target`, это заметно.
- Сторонние виджеты вне $mol (карты, редакторы кода, canvas) не воспроизводятся.
- Нативный скролл документа не пишется. У `$mol_scroll` позиция мемоизирована и восстанавливается сама.
- Гипер База не поддерживается: ленды в запись не попадают.
